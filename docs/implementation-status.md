# Implementation status

Updated 2026-10-01. The interview is closed and implementation of the entire accepted v1 is authorized. The release target remains [Q262's complete framework](framework-delivery-and-extensions.md#q262-keep-the-accepted-target-and-build-it-in-complete-stages). This document records evidence, not a reduction of that target.

Version `0.1.0-dev.1` remains a development build. Minecraft now executes published arena pairings with timed phases, capture objectives, block interaction objectives and their compositions. It captures the roster and content revision, waits for entity-ticking chunks, commits completion durably, and regroups participants through captured recovery locations. Recovery remains owed while a player is offline or no safe destination is available. Native graves, helper input, a grave camera, both spectator modes and voluntary living-observer viewing are connected. Captured revival protection blocks native damage, expires on simulation time, and persists across reconnects. Accepted hostile actions end it; helping another player revive does not. Other gameplay adapters remain pending; admission explicitly rejects their mechanic types. The adapter also provides build compatibility, per-world storage, GM delegation, bounded authoring transport, and an editor with validation/publication.

## Validation evidence

- `./gradlew build` compiles all three modules and both Fabric environments, runs core/storage/native-buffer tests, and packages the mod.
- Current unit totals: 193 core, 30 storage and 17 Fabric protocol/file tests, all passing. The native runner passes all 15 tests including Minecraft's control.
- Geometry tests cover interior cutouts missed by corner sampling, union seams, exclusion tangency, rotations, dimension/pose changes, cycles, containment and binding diagnostics. Reservation tests cover moved publications and bounded disconnected footprints.
- Core tests run YAML through the attempt coordinator. They cover objective progress, stale input, phase re-entry, live/latched conditions, timer cancellation, typed rule effects, conditional routes and frozen completion.
- Reuse tests cover typed defaults and constraints, independent occurrences, whole pattern constructors/input lists, scalar list entries, namespace preservation through nested forwarding, invalid references, cycles, depth and expanded-node limits. Required templates can be stored without instantiation. Current parameter kinds cover supported scalar, spatial, selection, group/role/aura/effect/damage-type and matcher fields; other content and asset kinds remain unavailable. Uninstantiated templates receive structural validation; concrete uses also run the capability decoder and cross-field checks.
- Composition tests cover private state, next-tick sequence/repeat boundaries, delays, parallel all/any arbitration, stopping precedence, deep settlement, independent reuse, rule ordering across persistent and phase scopes, cancellation and resource ceilings. Layers link their rules against the actual encounter after declarations are available. Export tests cover explicit field mapping, local-rule-before-export ordering, optional fields, explicit player narrowing, player aliases, duration/number parameter types, nested forwarding, repeat generations and private-handle rejection. Full contextual schemas and interface validation of required symbolic templates remain release work.
- Participant-rule tests cover pre-transition source filters, current-state guards, dead/offline lifecycle defaults, assisted helper selection, duplicate sequence rejection, causal ordering, and prevention of delivery to a later phase. Native grave notifications now come from committed operations instead of inferring revival from a later alive observation.
- Storage tests use real SQLite transactions and reopen the database. Subprocess crash tests of native save boundaries remain pending.
- `./gradlew :fabric:runGameTest` starts a disposable Fabric world. Fourteen Conclave tests verify native command authority, GM revocation despite a delayed grant callback, reference-counted chunk claims, stale native connection exclusion, a complete native capture/sequential-phase attempt, native death/respawn gamerules, placement rejection, actual player-file save confirmation, offline dead-player recovery from a pinned revision, persisted spectator-mode recovery, grave helper validation, protected native damage, hostile-action termination, protection expiry across a saved-player reconnect, and native block targeting geometry. The test setup follows [Fabric's testing documentation](https://docs.fabricmc.net/develop/automatic-testing). Test code has a separate source set and does not enter the distribution. No playable encounter bundle is shipped.

## Remaining v1 work

The accepted target still includes remaining typed parameters and event value kinds, complete typed capabilities, Location anchors and spatial controls, complete durable ownership/recovery, triggers and ready checks, remaining authoring/publication controls, NPCs, relics, auras, remaining revival/spectating integration, audience-aware presentation/assets, native rewards, coordinated backup/restore and upgrades, and installed-addon support.

Live client admission, resource readiness, privacy, integrated-server behavior, native save/restart recovery, and operational capacity/performance need release verification. Numeric limits remain development defaults pending measurement. Interfaces, catalog hashing and storage formats are experimental. The current development storage format is 2 and catalog identity format is v8. Older development databases are refused; no production-world migration has been performed. There is no automatic content or storage migration. Startup recovery supports untouched preparations and the current native player-recovery plan. Unsupported resource kinds preserve their records and block admission. Recovery search uses a bounded stable grid with horizontal block steps and vertical half-block steps; it never edits obstructing blocks. Performance limits and broader geometry/native compatibility still need release measurements.
